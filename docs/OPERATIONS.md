# التشغيل والتكامل — VORLDA

## الحالة الفعلية

هذه نسخة وظيفية للورشة والتحرير اليدوي والمحفظة التجريبية. التوليد بالذكاء الاصطناعي والتفكيك الدلالي والتتبع ثلاثي الأبعاد غير مفعّلة وغير منفذة بمجرد وجود نوع `generator`. مفاتيح مزود النماذج لم تُنشأ، تنفيذًا لطلب المالك تأجيل الإنشاء إلى ما بعد المراجعة. قاعدة `jobs` ومسار رد المبلغ يجهزان التخزين المستقبلي، ولا يمثلان خدمة توليد حية.

## تشغيل المشروع

- Node.js 24 مطلوب لتشغيل اختبارات SQLite دون تبعيات إضافية؛ الحزمة تدعم بناء Node.js 22.13 أو أحدث.
- تثبيت التبعيات: `npm ci`.
- التطوير: `npm run dev`، مع ربط D1 باسم `DB` وR2 باسم `BUCKET` عبر إعدادات Sites.
- التحقق: `npx tsc --noEmit` ثم `npm test`؛ يجري الاختبار بناءً فعليًا ثم اختبارات النواة والخادم وواجهة العرض على الخادم.
- توليد ترحيل بعد تعديل المخطط: `npm run db:generate`؛ لا تعدل ترحيلًا سبق تطبيقه.
- `APP_OWNER_EMAIL`: البريد المسموح له بإدارة الأسعار، يضبط في إعدادات الخادم فقط.
- `BILLING_MODE=test` افتراضي. الرصيد التجريبي منفصل تمامًا عن الحقيقي. يمكن لكل حساب إضافة 100 دولار تجريبية مرة واحدة دون تحويل مالي.

## الحسابات والخصوصية

هوية المستخدم تأتي من بوابة Sites الموثوقة. يجب أن تبقى بوابة التشغيل مسؤولة عن إزالة ترويسات الهوية الواردة من العميل وإضافة الهوية الموثقة؛ لا تنشر العامل مباشرة على إنترنت مفتوح يقبل ترويسات مزورة. المشروع الخاص يفرض عضوية إضافية: مالك، محرر، مراجع، أو مشاهد. تسجيل بريد في عضوية المشروع لا يدعو الشخص ولا يمنحه وصولًا إلى الموقع الخاص نفسه.

المسودة تحفظ بمقارنة رقم نسخة التحرير؛ تعارض الحفظ يعرض إنذارًا ويتيح الاحتفاظ بنسخة محلية. الإصدار المعتمد له رقم مستقل. عرض التكلفة يرتبط برقم النسخة المعتمدة ورقم المسودة ووضع الرصيد ومدة صلاحية خمس دقائق. يُستهلك رصيد الاشتراك أولًا، ثم الرصيد المشحون.

## الفوترة الحقيقية

تنفيذ Stripe اختياري في هذه النسخة، ولم يُنشأ حساب تاجر أو يُختبر دفع حي. يجب اختيار بوابة متاحة لحساب التاجر ومنطقته قبل التفعيل؛ وجود الشيفرة لا يثبت أهلية حساب تاجر معين.

متطلبات التفعيل بعد قرار المالك:

1. اعتماد الأسعار الشهرية والرصيد الممنوح في **ثلاث باقات فقط**، واعتماد أسعار الاستخدام وسياسة انتهاء/ترحيل الرصيد. حاليًا لا توجد صلاحية انتهاء تلقائية.
2. إنشاء أسعار شهرية بالدولار لدى التاجر، وربط `stripePriceId` الموافق لكل باقة. يتحقق الخادم من عملة السعر ومقداره ودورته قبل إنشاء جلسة.
3. ضبط `APP_ORIGIN` على عنوان التطبيق الفعلي، و`STRIPE_SECRET_KEY` و`STRIPE_WEBHOOK_SECRET` كأسرار خادم. لا تُدخل المفاتيح في المشروع أو المتصفح.
4. تهيئة نقطة الإشعار `POST /api/payments/webhook`. الأحداث المعالجة: `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.expired`, `invoice.paid`, `customer.subscription.updated`, `customer.subscription.deleted`. تسجل أحداث الاعتراض أو رد المبلغ للمراجعة اليدوية.
5. إجراء اختبارات بوابة الدفع الفعلية في بيئة تاجر اختبار منفصلة قبل تشغيل `BILLING_MODE=live`. النسخة الحالية تتجاهل منح الرصيد من الأحداث غير الحية، وتتيح محاكاة المنح محليًا عبر اختبارات الخادم. لا تحول الرصيد التجريبي إلى أموال.

الاشتراك يمنح رصيده عبر فاتورة دورية مدفوعة، وليس بمجرد العودة من صفحة الدفع. دفع الاستهلاك المسبق يشحن المحفظة؛ لا يوجد خصم بطاقة تلقائي عند نفاد الرصيد. قيود فريدة تمنع تكرار المنح حسب معرف الجلسة أو الفاتورة، وتمنع جلستين مفتوحتين للاشتراك للحساب نفسه. فواتير التناسب الجزئي لا تمنح باقة شهرية ثانية.

رد مدفوعات التاجر والاعتراضات تحتاج حاليًا مراجعة وتسوية دفترية يدوية؛ لا توجد واجهة تسوية مالية عامة، ولا رد بطاقة تلقائي. تبديل الاشتراكات مع احتساب الفروقات ليس منفذًا. يجب ضبط بوابة إدارة التاجر للسماح بالإلغاء وإدارة وسيلة الدفع فقط حتى استكمال هذا المسار. لا تصف هذه النسخة بأنها جاهزة لتحصيل أموال العملاء قبل حسم هذه المتطلبات واختبارها.

## التكامل الخارجي

من شاشة المشروع أنشئ رمزًا محدودًا بمشروع واحد وصلاحيات `read`, `write`, `execute` وحد أعلى لكل تكلفة معتمدة. يعرض مرة واحدة، يخزن ملخص SHA-256 فقط، وينتهي بعد 30 يومًا. إلغاؤه يسري فورًا. بوابة خصوصية Sites تبقى سارية؛ قد تحتاج هوية وصول منفصلة للموقع الخاص.

الواجهات الأساسية:

| الواجهة | الوظيفة |
|---|---|
| `GET /api/projects/:id` | قراءة المخطط والملفات والسجل حسب العضوية |
| `PATCH /api/projects/:id` | حفظ `draft` مع `revision` و`draftRevision` أو إعادة التسمية |
| `POST /api/projects/:id/quote` | عرض ثابت للمخطط المقترح مع رقم نسخته |
| `POST /api/quotes/apply` | تطبيق `quoteId` مرة واحدة وإرفاق `requestId` للتتبع |
| `POST /api/projects/:id/import` | إدخال مشروع سابق إلى مشروع فارغ فقط، مجانًا |
| `POST /api/projects/:id/assets` | استيراد ملف أصلي عبر `FormData.file` |
| `POST /api/projects/:id/publish` | نشر النسخة المعتمدة لمستخدمي المشروع داخل الموقع الخاص |
| `GET /api/projects/:id/export` | إخراج المخطط المعتمد؛ `?format=html` لإخراج HTML |
| `GET /api/assets/:id` | ملف محمي بالعضوية، يدعم نطاق البايتات لتقديم الوسائط |

عمليات الرسم اليدوي تستخدم مخططًا مصرحًا، والتحويلات وقت التشغيل تستخدم قائمة محدودة `filter`, `sort`, `limit`, `set`، ولا تنفذ تعليمات نصية عبر `eval`. كود HTML المخصص داخل iframe معزول دون وصول إلى بيانات الورشة أو الشبكة البرمجية.

## الحدود المتبقية

- تتضمن `docs/IMPLEMENTATION-COVERAGE.md` حالة كل قسم من الأقسام الكانونية 0–173. القراءة والمطابقة لا تعني تنفيذ كل محرك متخصص.
- الرسم اليدوي يتضمن تحريكًا وتحجيمًا ودورانًا وقناعًا هندسيًا وفلاتر، ولا يتضمن استخراج أجسام ذكيًا أو ملاءمة ملابس أو استعادة أجزاء خفية.
- التصدير الفلمي الحالي تسجيل متصفح في الزمن الحقيقي، حتى 180 ثانية وأربعة ميغابكسل للإطار. يتأثر بالمتصفح وتوفر تشغيل الوسائط وبقاء النافذة ظاهرة. التصدير الاحترافي الطويل بالخادم غير منفذ.
- المعاينة والتصدير قد يحتاجان استيراد الوسائط الخارجية أولًا عند منع الخادم الخارجي وصول CORS. تُضمّن الملفات المستوردة في تصدير HTML والمشروع.
- النماذج تحفظ ردودًا فعلية عند النشر الخاص. تصدير HTML وحده يتطلب خادم استقبال خارجي؛ حزمة مصدر ZIP الجديدة توفر خادم Node/SQLite محدودًا للنماذج. تخزين إجراءات التطبيق الأخرى محلي في جهاز الزائر، وليس قاعدة بيانات عامة مولدة لكل تطبيق. راجع [حدود الحزمة والتخزين](RELEASE-PORTABILITY.md).
- المحرر يعرض البيانات والمكونات بصريًا؛ لا يجري تحليلاً دلاليًا تلقائيًا لأي ملف مستورد. استخدام رمز الصوت الزخرفي ليس استخراجًا للموجة الصوتية.
- لم تُجر اختبارات نقر أو تسجيل فيديو في متصفح خلال هذه الجلسة؛ الاختبارات المنفذة للخادم والنواة والبناء وعرض HTML على الخادم.

المراجع الفنية: [Stripe Webhooks](https://docs.stripe.com/webhooks)، [Idempotent requests](https://docs.stripe.com/api/idempotent_requests)، [Subscription webhooks](https://docs.stripe.com/billing/subscriptions/webhooks).


## تكامل الإنتاج الجديد

`REPLICATE_API_TOKEN` مفتاح خادم فقط؛ لا يدخل الحزمة أو المتصفح. `REPLICATE_WEBHOOK_SECRET` سلسلة عشوائية مستقلة بطول 32 حرفًا على الأقل لتوقيع عنوان إشعار كل عملية. `APP_ORIGIN` عنوان HTTPS موثوق. جميعها تُدار في إعدادات بيئة الخادم، مع BILLING_MODE=live واعتماد سعر run قبل طلب التوليد. القيمة التجريبية لا تعتمد الأسعار الحية تلقائيًا.

المزوّد المربوط في الشفرة: `black-forest-labs/flux-1.1-pro` فقط. صورة PNG، ونسب أبعاد محددة؛ لا نموذج أو عنوان اتصال يرسله المستخدم. تنزيل النتائج يقتصر على HTTPS ضمن replicate.delivery، بلا تحويلات وبحد 25 MiB.

مسار الإشعار `/api/production/callback/:taskId?token=...` محمي بتوقيع خاص بالعملية، ثم يجلب الخادم حالة العملية من المزوّد. المسار يجب أن يصل إليه المزوّد قبل تفعيل الإنتاج؛ حماية الموقع الخاص لا تسمح بافتراض ذلك. Stripe لديه الشرط نفسه لمسار إشعار الدفع. لا تُفتح الورشة للعامة لمجرد تسهيل الإشعارات.

عند غموض استلام طلب مدفوع، يظل محجوزًا في حالة uncertain حتى مراجعة مالك الموقع. `GET /api/admin/production` يعرض الحالات؛ إعادة الرصيد تتطلب سببًا وتسجل مرة واحدة. لا تستخدم إعادة المحاولة العمياء لبدء طلبات المزوّد.

استحقاقات الاشتراك تعتمد `paid_until` المستمد من فترة الاشتراك عند الفاتورة الشهرية المدفوعة. قبل تفعيل تغييرات الباقات في بوابة التاجر، يلزم إكمال مطابقة الفاتورة والسعر والباقة الجديدة؛ النسخة الحالية لا تدّعي دعم ترقية فوترة نسبية.
