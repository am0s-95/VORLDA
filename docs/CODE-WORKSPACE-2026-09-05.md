# مساحة البرمجة والتوافق — 5 سبتمبر 2026

## نطاق طلب المالك

التطبيق يجب أن يتعامل مع الكود ومشاريع البرمجة والنودز وبيئات تشغيل مختلفة، وأن يحتفظ بالأكواد وطريقة البناء ضمن التصدير. التنفيذ التالي يوسع الورشة خارج مخطط HTML الخاص بـVORLDA، دون مساواة قراءة الكود بتشغيله على كل المعالجات.

## التنفيذ

- زر «البرمجة» داخل شريط الورشة يفتح مساحة ملفات حقيقية مرتبطة بالمشروع.
- استيراد ZIP مخزّن أو Deflate، أو عدة ملفات، أو مجلد من المتصفحات الداعمة. تبقى مسارات ZIP كما هي؛ استيراد المجلد يزيل اسم المجلد الخارجي الذي اختاره المستخدم فقط.
- حفظ ملفات نص UTF-8 بما فيها BOM وCRLF، وملفات ثنائية بترميز يحفظ بايتاتها. الحفاظ على ملفات الحزم والتبعيات المقفلة داخل المصدر دون تثبيت أو تشغيل أثناء الاستيراد.
- حدود معلنة: 400 ملف و2 MB من المصدر للوحدة، 12 MB للأرشيف المضغوط/اختيار الملفات، مع حد المخطط العام 4 MB. مجلدات الاعتماد الشائعة وأسماء ملفات الأسرار المعروفة تُستبعد مع بيانها؛ لا يوجد ادعاء بكشف كل سر داخل نص الكود.
- تحرير الملف ونسخه وتنزيله، وإضافة ملفات وحذفها. حفظ تعديل الملف يضعه في مسودة المشروع ويستخدم الحفظ السحابي والصلاحيات وتعارض المراجعات الحالية. يُطلب تأكيد عند إغلاق المحرر مع تعديل لم يُحفظ.
- كل مشروع مصدر يظهر كقطعة كود في الورشة؛ ملفاتها تنتقل مع نسخ المشروع وسجله وتصديره. روابط القطع البصرية لا تشغّل سكربتات المشروع تلقائيًا.
- قراءة متطلبات Node/React/Next/Vue/Nuxt/Svelte/Angular/Express/Vite، ومشاريع Python/Go/Rust/JVM/.NET/PHP/Ruby/C/C++/Flutter/Swift والحاويات من الملفات المعروفة. هذا تعرف بنيوي، وليس إثبات بناء لكل إطار أو استيعاب لكل صيغة إعداد ممكنة.
- معاينة HTML ذاتي الاحتواء داخل iframe معزول؛ لا ملفات نسبية أو خادم أو تثبيت npm داخل هذه المعاينة. JavaScript غير المنتهي يمكن أن يعطل نافذة المتصفح؛ الإطار ليس عزلًا للموارد.
- أمثلة مصدر قابلة للتصدير لـHTML/JS وNode.js وPython وC/GCC.
- مخطط مهام صريح: معرفات، أوامر كمصفوفة معاملات، تبعيات، ومجلد تشغيل. يرفض المراجع المفقودة والدورات. يستخرج سكربتات package.json دون تشغيلها.
- حزمة تصدير تحتفظ بالمصدر وتضيف vorlda-tools مع بيان المهام ومنفذ محلي. يقبل تشغيلًا صريحًا بعد مراجعة الأوامر، يدعم توازيًا 1–4، وينفذ كل تبعية مشتركة مرة واحدة. الفشل يمنع التبعيات اللاحقة، والمهلة 120 ثانية. على POSIX يوقف مجموعة العمليات عند انتهاء المهلة أو مقاطعة المنفذ.
- المنفذ المحلي **ليس sandbox**؛ لا يُستخدم لتشغيل كود مجهول على خادم المنصة. Windows لا يُشغّل سكربتات npm/pnpm/yarn عبر shell من هذا المنفذ؛ تستخدم الطرفية أو WSL. إيقاف شجرة عمليات Windows غير مضمون بهذه الآلية.
- معاينة بنية ملفات n8n (workflow واحد) وNode-RED (مصفوفة flows) الأصلية: النودز والروابط وإعدادات النود والمراجع المفقودة. حد العرض 250 نود و2000 رابط. لا تحويل بين الصيغ ولا تشغيل للمحرك، ودلالات حدود subflows ومراجع config الخاصة بكل نوع ليست محللة بالكامل.

## توافق التشغيل الصادق

| القدرة | الحالة |
|---|---|
| قراءة وتعديل وتصدير كود بلغات مختلفة | منفذة ضمن ميزانية الملفات |
| HTML/CSS/JS المضمن في ملف واحد | معاينة معزولة موجودة؛ لا اختبار متصفح تفاعلي جديد |
| Node.js وPython وC/GCC | تنفيذ فعلي للأمثلة المصدرة واختبارات المهام داخل بيئة Linux الحالية |
| React/Next/Vue وسائر أطر الحزم | اكتشاف إعدادات واحتفاظ بالمصدر؛ لا بناء حي مستضاف مربوط |
| n8n وNode-RED | عرض بنية وتحليل روابط؛ التنفيذ يحتاج محركهما ونودزهما واعتماداتهما |
| x64/ARM، Windows/macOS/Linux، GPU | لا ضمان شامل؛ يجب بناء التبعيات واختبار كل هدف فعليًا |
| توليد التطبيق بواسطة فريق وكلاء | غير منفذ في هذا التحديث |

لا تنفذ ملفات المستخدم داخل Cloudflare Worker. إعداد واجهة طرفية دون محرك عزل فعلي كان سيعطي وعدًا كاذبًا ويعرض المنصة للخطر. التشغيل المستضاف يحتاج ربط sandbox مناسب مع عزل المشاريع وميزانيات الموارد والشبكة والسجلات وإنهاء الجلسة.

## أدلة البحث

- [Cloudflare Node compatibility](https://developers.cloudflare.com/workers/runtime-apis/nodejs/): دعم جزئي؛ child_process وvm وwasi ليست بدائل تنفيذ أصلية كاملة.
- [Cloudflare limits](https://developers.cloudflare.com/workers/platform/limits/): ميزانيات الذاكرة والتنفيذ تمنع اعتبار Worker جهاز بناء عامًا.
- [Cloudflare Sandbox](https://developers.cloudflare.com/sandbox/) و[نموذج الأمان](https://developers.cloudflare.com/sandbox/concepts/security/): خيار لربط تنفيذ Linux منفصل مستقبلًا، وليس مفعّلًا في هذا الإصدار.
- [Node native addons](https://nodejs.org/api/addons.html) و[حدود ABI](https://nodejs.org/api/n-api.html#implications-of-abi-stability): المصدر/Node-API لا يضمنان تلقائيًا توافق كل نظام ومعمارية واعتماد أصلي.
- [n8n connections](https://github.com/n8n-io/n8n/blob/master/packages/workflow/src/interfaces.ts) و[تصدير workflow](https://docs.n8n.io/build/manage-workflows/export-and-import): الربط بالأسماء، وقد تحتوي ملفات التصدير مراجع اعتماد أو قيمًا حساسة ضمن معلمات HTTP.
- [Node-RED flow types](https://nodered.org/docs/api/admin/types) و[credentials](https://nodered.org/docs/creating-nodes/credentials): الربط بالمعرفات؛ اعتماداته الرسمية منفصلة، دون ضمان أن الكود الحر خالٍ من أسرار.

## تحقق الإصدار

الاختبارات تتحقق من حفظ BOM والملفات الثنائية وCRLF، حد المصدر الكامل ذهابًا وإيابًا، استبعاد التبعيات دون اعتماد على ترتيب ZIP، رفض المسارات المتعارضة والروابط والأرشيف التالف، قواعد المهام، التحليل دون تشغيل، عزل مشروع الكود، تشغيل Node/Python/C، التوازي الحقيقي وترتيب التبعيات وإيقاف العمليات. نتائج الجولة النهائية في VALIDATION.md.
