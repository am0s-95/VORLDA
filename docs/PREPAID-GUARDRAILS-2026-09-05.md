## قواعد المنحة والمحفظة

- المحفظة النقدية للخدمات بقيت برصيدَي الاشتراك والشحن. `total` في API يشير إليهما فقط. `promotion.balance` رصيد منفصل مؤهل للقوالب؛ لا يجوز للواجهة إظهاره كرصد متاح لتوليد الصور.
- الاستهلاك المؤهل للقوالب: الترحيبي أولًا، ثم الاشتراك، ثم الشحن. جميع الأرقام وحدات دولار صحيحة بمقياس مليون، دون حساب عشري مالي.

- بصمة SHA-256 للبريد بيانات مستعارة الهوية وليست مجهولة الهوية. يلزم تحديد سياسة الاحتفاظ والخصوصية قبل إطلاق عام. الهوية والبريد مصدرهما بوابة Sites الموثوقة، وليس جسم طلب العميل. لا يُقبل تنفيذ المنحة أو الشراء عبر API token.

## مسار توليد الصور

- عرض السعر يبيّن رصيد الشحن والاشتراك المؤهل. التنفيذ يتحقق منه على الخادم، ويحجز مساحة حتى 25 MiB للمخرج ضمن المعاملة الذرية التي تخصم تكلفة العملية وتتحقق من التوازي وميزانية عضو الفريق.
- لا يبدأ استدعاء المزوّد إذا لم يتوفر الرصيد أو مساحة المخرج أو حد التوازي/الصرف. تكرار الطلب لا يرسل توليدًا جديدًا.
- فشل التوليد المؤكد يعيد المبلغ إلى مصدريه ويحرر مساحة المخرج مرة واحدة.
- إذا نجح المزوّد وتعثر تنزيل/حفظ الصورة، تصبح الحالة `delivery_failed`. يُحفظ الخصم والمساحة بدل رد مال عمل نُفذ بالفعل. «تحديث» في سجل الإنتاج يعيد محاولة التسليم بلا توليد مدفوع جديد.
- نتائج قبول المزوّد غير المؤكدة لا تُعاد تلقائيًا. مراجعة المالك والاسترداد الموثق متاحان. التسليم النهائي غير الممكن أو خطأ المنصة يحتاج مراجعة عادلة؛ لا تدّعي هذه الحالة وحدها تحقق هامش ربح.
- لا يوجد بعد صف عمل دائم أو مجدول مصالحة مستقل يعالج كل انقطاع. بعض الحالات تحتاج callback أو فتح سجل العمليات أو مراجعة المالك. المزوّد والدفعات الحقيقية غير مربوطين في الموقع الحالي؛ اختبارات المزوّد بديل محلي، بلا خصم خارجي.

## حدود التخزين والطلبات

- جميع حمولات المشاريع والمكتبة الجديدة، حتى الصغيرة، تحفظ كأجسام R2 ثابتة ومحمية ببصمة. تشير المسودة والنسخ والنشر إلى الجسم نفسه عند إعادة الاستخدام، ويحسب مرة واحدة.
- تشمل المحاسبة الوسائط المرفوعة، أجسام المشروع والنسخ السابقة، الحجوزات قيد الإنجاز، وأحجام JSON القديمة المضمنة في الجداول. لا تمثل هذه الأرقام فاتورة D1/R2 الكاملة أو قياس CPU أو الشبكة أو فهارس قاعدة البيانات.
- أول وصول يفهرس مؤشرات الملفات القديمة لكل المالك، بما فيها المشاريع المؤرشفة والمنشورات المعطلة وسجلات النسخ والعروض والمكتبة. المؤشر التالف يوقف قبول تخزين إضافي برسالة إصلاح واضحة؛ لا يُتجاهل كي لا تنقص المحاسبة.
- فحص المساحة وإدخال الحجز عبارة SQL واحدة. تحويل الحجز إلى جسم مسجل معاملة واحدة. إعادة استخدام جسم مفقود/تالف لا تُبلغ عن حفظ ناجح؛ يُكتب جسم بديل.
- فقدان CAS لا يحذف أجسامًا قد تشير إليها نسخة محفوظة. عند خسارة شراء متزامن مع نتيجة معاملة مؤكدة، تُحذف أجسام محاولة الإنشاء غير المسلمة. عند فشل/غموض نتيجة قاعدة البيانات تبقى البايتات محسوبة للمراجعة، ولا تُحذف تخمينيًا. لم يُنفذ جامع نفايات شامل أو مصالحة تلقائية للحجوزات اليتيمة بعد.
- الأرشفة لا تحرر تاريخ المشروع تلقائيًا. بلوغ الحد يمنع تخزينًا جديدًا، ويحافظ على قراءة وتصدير العمل الموجود ضمن حدود الطلبات.
