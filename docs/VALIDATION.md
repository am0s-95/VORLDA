# التحقق المنفذ — 5 سبتمبر 2026

## أحدث جولة: إدارة التطبيق المصدّر وعزل الاختبار

على فرع `review/isolated-admin-export` فقط: **85 اختبارًا ناجحًا، صفر فشل** عبر `node --test tests/*.test.mjs`. نجح فحص TypeScript وبناء التطبيق والعامل، ومرّ `git diff --check` دون ملاحظات. لم تُدمج هذه الجولة في `main` ولم تُنشر على الموقع الحي.

تشمل الإضافات تسعة اختبارات لحساب الإدارة الاختياري في الحزمة المصدّرة، واختبارًا لعزل بيئتي ورشة محليتين. تغطي التهيئة مرة واحدة، فرض تغيير كلمة المرور الأولية، رفض Origin/CSRF غير الصحيحين، تدوير الجلسات وإبطالها عند الاستعادة، انتهاء الصلاحية، سباق الاستعادة مع التحقق، حدود المحاولات، خصائص ملفات الارتباط في الإنتاج، فصل قواعد بيانات وحسابات التطوير والإنتاج، وعدم تضمين كلمات المرور والجلسات والردود في حزمة المصدر أو الاستيراد.

اختبار الواجهة يستخدم Node VM وبديل DOM محدودًا لإثبات مسح الردود وكلمات المرور عند الخروج أو انتهاء الجلسة وتجاهل الردود المتأخرة؛ **ليس اختبار متصفح أو لمس فعليًا**. واختبار عزل الورشة يستخدم بيئات D1/R2 اختبارية مستقلة؛ **لم يُنشأ حساب اختبار سحابي أو نشر staging مستقل**.

بدأ خادم المعاينة، لكن اتصال المتصفح تعذّر قبل فتح أي تبويب، حتى بعد محاولة إعادة واحدة. لذلك لا يُدّعى اجتياز تسجيل الدخول أو اكتمال التحقق البصري/اللمسي. يبقى فحص المتصفح الفعلي شرطًا قبل الدمج. لم تتغير حماية دخول المنصة، ولم يُستخدم تجاوز للمصادقة، ولم تُجر مدفوعات حقيقية أو اختبارات حمل منشورة. [المتطلبات وحدود التنفيذ](OWNER-ADMIN-AND-TESTING-2026-09-05.md).

## الجولة السابقة: اللمس والتخزين والتصدير

نجح بناء التطبيق والعامل وفحص TypeScript. مجموعة الاختبارات الكاملة: **75 ناجحة، صفر فشل**. تشمل 18 اختبارًا جديدًا لحركة اللمس وتخزين المخططات الكبيرة وحزمة المصدر. [تفاصيل التنفيذ والحدود](RELEASE-PORTABILITY.md).

جُرب فك ZIP وبناء وتشغيل الحزمة فعليًا خارج مجلد المنصة، وحفظ الردود ثم قراءتها بعد إعادة التشغيل، ورفض كشف ملفات الخادم/القاعدة، وHost/Origin المرفوضين، والتكرار المتعارض وحد المعدل. اختبار Host يستخدم طلب HTTP مباشرًا لأن fetch لا يمرر ترويسة Host البديلة في بيئة الاختبار.

فحص المتصفح أظهر واجهة الورشة ثم توقف عند طلب تسجيل الدخول؛ لم تُجر تجربة تحرير موثقة أو محاكاة لمس حقيقية. لا اختبار حمل منشور أو ربط تاجر/نموذج حي. حُفظت التعديلات دون نشر هذه الجولة أو تغيير خصوصية الموقع. الفحوص التالية سجل الجولة السابقة، وليست نتيجة جديدة مستقلة.

## الجولة السابقة

نجح التحقق النهائي قبل النشر الخاص:

| الفحص | النتيجة |
|---|---|
| ملفات الأرشيف الأصلية | 14/14 دون تغيير؛ مقارنة SHA-256 بين النسخة المرفوعة والمستودع |
| تتبع المواصفة | الأقسام الكانونية 0–173، لكل منها حالة وملاحظة |
| TypeScript | دون أخطاء |
| بناء التطبيق والعامل | ناجح |
| اختبارات النواة والخادم والدفع والعرض | 57 ناجحة، صفر فشل |
| تسرب التعديلات الجزئي | اختبار فشل معاملة يثبت تراجع المخطط والخصم والدفتر معًا |
| تعارض المسودات | الحفظ القديم وطلب الخصم القديم مرفوضان |
| منع الخصم المتكرر | طلبات متزامنة لنفس العرض تنتج عملية وخصمًا واحدين |
| استحقاق الاشتراك | الإشعار المكرر والفاتورة نفسها لا يمنحان الرصيد مرتين؛ كل فاتورة شهرية جديدة تمنح الرصيد مرة واحدة |
| رصيد الاختبار/الحقيقي | فصل تام؛ أحداث تاجر الاختبار لا تضيف رصيدًا ماليًا حيًا |
| المنشورات والنماذج | وصول بحسب العضوية، تحقق من الحقول، ردود محفوظة دون تكرار |
| الوسائط | وصول محمي، استيراد مجاني، رفض SVG نشط، دعم نطاق البايتات |

اختبارات Stripe تستخدم بدائل محلية محددة صراحة، مع توقيع HMAC حقيقي للرسالة التجريبية. لم تتصل بحساب تاجر ولم تنفذ أي دفع حقيقي. لم تستخدم أي مفتاح نماذج ولم تنفذ توليدًا بالذكاء الاصطناعي.

فحص HTML يجري على الخادم وفي المترجم. لم تُجر اختبارات تفاعل متصفح، أو جودة بصرية، أو تسجيل/تشغيل ملف فيديو في المتصفح خلال هذه الجلسة. الحدود غير المكتملة مذكورة في `IMPLEMENTATION-COVERAGE.md` و`OPERATIONS.md`؛ نجاح الاختبارات ليس إثباتًا لاكتمال جميع محركات الرؤية.


## فحوص الجولة الإضافية

- الباقات الثلاث وأسعارها، واختلاف الاستحقاقات بين الاختبار والحساب الحي والفترة المدفوعة.
- مجانية التحرير اليدوي حتى عند وجود إعداد رسوم قديم، ورفض عرض يدوي قديم يحمل مبلغًا.
- تكرار ثمانية طلبات تنفيذ مدفوعة لنفس العرض ينتج خصمًا واحدًا؛ اختبار تراجع المعاملة عند فشل كتابة الدفتر.
- أولوية رصيد الاشتراك، رفض نقص الرصيد، انتهاء العرض، اختلاف وضع الفوترة، إعادة الرصيد مرة واحدة إلى وضعه ومصدره الأصليين.
- حدود التخزين أثناء الحجز المتزامن، والاحتفاظ بالبيانات عند تخفيض الباقة.
- صلاحيات مكتبة الإنتاج والهويات وعزل الحسابات ومراجعات الموارد وحدود العدد ورفض نقل روابط وسائط خاصة ضمن الإعداد.
- حد مقاعد Studio عبر المشاريع، وحدود صرف الأعضاء من محفظة المالك، وإيقاف كتابة الفريق عند تخفيض الباقة.
- اشتراط اعتماد نسخة النشر، وعدم قبول اعتماد نسخة قديمة، وعدم حبس النشر نهائيًا بعد التخفيض.
- عدم تشغيل التوليد غير المربوط أو استخدام رصيد اختبار لطلب نموذج حقيقي.
- مزوّد اختباري يثبت حد العمليات المتزامنة، عدم تكرار بدء التوليد، حفظ الصورة الناتجة خصوصيًا، وصحة الاسترداد عند فشل المزوّد.
- غموض رد المزوّد يتوقف للمراجعة بدل إعادة الطلب؛ التسوية تتطلب صلاحية المالك وسببًا مسجلًا.
- إشعار الإنجاز يرفض توقيعًا مزورًا أو إيصالًا مختلفًا ويجلب حالة المزوّد الحقيقية؛ تكراره لا يعيد الرصيد مرتين.
- حد التصدير الجماعي وصلاحياته، واستعادة المشاريع المؤرشفة دون فقدان المخطط.
- تحقق مستقل بواسطة Python zipfile من ملف ZIP الناتج: اسما ملفين، اسم عربي UTF-8، ومحتويات CRC سليمة.
- بناء Worker النهائي يعرض VORLDA وشعارها ومداخل المكتبة والإنتاج، ويحجب API غير الموثق.

ملفات الأرشيف الأربعة عشر طوبقت مرة أخرى مع ZIP المرفوع: كلها دون تغيير. هذا لا يعني إعادة قراءة كل بند من المواصفة في هذه الجولة؛ المراجعة السابقة محفوظة واستُخدمت لتحديد مواضع التغيير.
