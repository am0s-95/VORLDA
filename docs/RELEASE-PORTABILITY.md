# تحسين اللمس والتخزين والتصدير المستقل

هذا وصف النسخة 3 السابقة. التطوير اللاحق لحساب الإدارة الاختياري وعزل بيئة التشغيل محفوظ في [وثيقة المالك الجديدة](OWNER-ADMIN-AND-TESTING-2026-09-05.md)، على فرع مراجعة منفصل دون نشر أو دمج.

هذه جولة تنفيذ محددة، وليست إكمالًا لكل المنتج أو تصريحًا بالنشر الجماهيري.

## ما تغير

- لوحة الهاتف: فصل السحب عن اللمس العابر، تكبير وتحريك بإصبعين، إنهاء آمن للإلغاء وفقد الالتقاط، التقاط المؤشر على اللوحة المستقرة، وإيقاف الإيماءة عند تبديل المشروع. لا تُفتح لوحة الخصائص تلقائيًا أثناء سحب عنصر باللمس. إعادة ترتيب عناصر الصف/العمود تحترم خصائص الهاتف والإخفاء. الترتيب الجماعي داخل التدفق غير مدعوم؛ تظهر رسالة تطلب عنصرًا واحدًا. التحديد المتعدد في التخطيط الحر يبقى متاحًا.
- مخططات المشاريع والنسخ الكبيرة تُحفظ ككائنات R2 ثابتة؛ تحمل صفوف D1 مرجعًا صغيرًا مع حجم وبصمة SHA-256. الملفات الصغيرة تبقى داخل الصف. تتحول القيم القديمة تدريجيًا عند الكتابة. حد المخطط 4,000,000 بايت UTF-8، وليس عدد محارف. الحفاظ على ذرية الاعتماد والدفتر والرصيد والنسخة داخل معاملة SQL واحدة.
- فشل رفع الكائن يسبق تعديل المرجع ولا يمحو النسخة السابقة. مرجع غير صحيح أو مفقود ينتج خطأ واضحًا، ولا يستبدل المشروع بمشروع فارغ. مكتبة الإعدادات تحمل بيانات وصفية فقط ثم تجلب المخطط المختار، بدل تجميع كل مخططات الحساب في ذاكرة العامل.
- خيار ZIP جديد يضم project.vorlda.json، الأصول المضمنة، المصدر الحقيقي للمخطط والمترجم والتحقق من النماذج، ملفات البناء والخادم والاختبار، README، إعدادات نموذجية دون أسرار، وبصمات الملفات.
- خادم الحزمة مستقل بلا اعتماد على بوابة Sites أو ترويسات هويتها. يحتاج Node >=24 دون تنزيل مكتبات. يحفظ ردود النماذج في SQLite؛ لا يتيح المصدر أو قاعدة البيانات عبر HTTP. الإعداد الافتراضي محلي؛ التشغيل العام يحتاج تصريحًا صريحًا وإعداد HTTPS. يتحقق من Host وOrigin وحجم وحقول الطلب وتكراره، ويحدد المعدل.
- تحقق مسبق من ملف الاستيراد وأصوله قبل إنشاء مشروع جديد. سقف المتصفح الحالي للأصول المضمنة 16 MiB، مع ميزانية إضافية توسعية لـHTML تمنع تكرار صورة واحدة من استهلاك ذاكرة هائلة. المشاريع الإعلامية الأضخم تحتاج مسار تصدير تدفقي غير منفذ بعد.

## التحقق

- اختبارات رياضية وإجرائية لحركة إصبعين، الإلغاء، طبقات متداخلة، فجوات وإخفاء خاص بالهاتف. هذه ليست تجربة فعلية على iPhone.
- اختبارات تخزين كبيرة بالعربية، حدود صفوف أقل من 2 MB، تراجع المعاملة، فشل R2، مراجع تالفة أو خارج نطاق المشروع، تنافس الاستيراد، وقراءة إعداد واحد بدل تحميل الجميع.
- فك ZIP فعلي عبر Python zipfile مع CRC، ثم npm test وتشغيل خادم Node في مجلد مؤقت بلا node_modules أو مفاتيح منصة. فحص الصفحة والملفات المضمنة، رفض كشف المصدر والقاعدة، رفض Host/Origin غير المسموحين، رفض بيانات خاطئة وتعارض معرف الطلب، استمرار الردود بعد إعادة التشغيل، وتحديد المعدل.
- التحقق من إعادة قراءة المخطط الأصلي عبر نفس مدقق الاستيراد. لم يجر اختبار نقر استيراد الحزمة عبر المتصفح؛ المتصفح توقف عند تسجيل الدخول ولم يتم تجاوزه.
- مراجعة ثانية مستقلة للقراءة فقط كشفت هندسة التدفق، تحريك الأحفاد مرتين، Host المحلي، وتضخيم الأصول؛ صُححت وأضافت الاختبارات تغطية لها.

## الحدود المتبقية

1. لا توجد منظومة وكلاء AI داخل التطبيق. لا يجب وصف توازي الاختبارات أو مراجعي التطوير بأنه وكلاء منتج. يلزم تنفيذ عامل مهام دائم، مدير عمليات، صلاحيات أدوات دقيقة، ميزانيات محجوزة، موافقات نشر/دفع، إلغاء واستئناف، وتتبع محاولات وتعويضات. أدوار المخطط/المنفذ/المختبر/المراجع لا تمنح نفسها صلاحيات؛ يعمل كل دور تحت تفويض مشروع وخطوة محددين. الملفات المستقلة فقط يمكن تنفيذها بالتوازي، ثم مراجعة ودمج نسخة متوقعة.
2. لا تفعيل لمزوّد نموذج حقيقي أو دفع تاجر حي. الربط الآمن واختبار سقف تكلفة منخفض يسبقان أي تشغيل مدفوع. لا تُرسل المفاتيح في المحادثة ولا تُضمّن في تصدير مشروع العميل.
3. مصدر التطبيق المصدّر يخص تطبيق VORLDA الأصلي، وليس نسخة من كامل الورشة. تعديل project.vorlda.json يعود للمحرر؛ تعديل الكود المباشر لا يتحول تلقائيًا إلى مخطط بصري. استيراد مستودع React/Flutter عشوائي غير منفذ.
4. خادم الحزمة عام للنماذج عند تفعيل الوضع العام، وليس حسابات مستخدمين أو متجرًا أو منصة متعددة المستأجرين. SQLite أحادي النسخة يحتاج قرصًا دائمًا ونسخًا احتياطية وسياسة احتفاظ وموافقة على جمع البيانات. وسيط عكسي قد يجعل الزوار يشتركون في حد عنوان واحد؛ يلزم ضبط حماية الدخول قبل التوسع.
5. كائنات R2 غير المشار إليها بعد خسارة تنافس أو فشل معاملة لا تُحذف فورًا حفاظًا على السلامة. يلزم جامع قمامة مؤجل يعتمد جميع المراجع وفترة سماح، وحدود لحجم سجل المخططات، قبل الإطلاق الواسع. حدود تخزين الخطة الحالية تحسب الأصول الإعلامية ولا تحتسب هذه المخططات بعد.
6. لا اختبار ضغط منشور أو إثبات عدد مستخدمين. فصل التخزين لا يلغي اختناق قاعدة مشتركة أو سقوف المزوّدين. يلزم قياس استجابة p95، زمن انتظار الطابور، أخطاء وعمليات مكررة، وكلفة المستخدم، واختبار استعادة النسخ قبل إعلان السعة.
7. استفادة المنتج من الاستخدام تكون بقياس فشل البناء، نجاح الاختبارات، إعادة المحاولة، وقت التسليم والتكلفة بموافقة مناسبة؛ لا نسخ تلقائي لكود العملاء ولا ادعاء تدريب تلقائي. لم ينفذ هذا القياس/التعلم بعد.
